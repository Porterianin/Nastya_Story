# Nastya Story

Единый репозиторий проекта игры **Nastya Story**. Репозиторий является основным источником истины для игрового кода, проектной документации, базы мира, контента и заданий на реализацию.

## Главный принцип

**Чат сам по себе не является каноном проекта.** Обсуждение становится каноническим только после фиксации решения в соответствующем файле репозитория. При противоречии между памятью AI/историей чата и актуальными файлами репозитория приоритет имеют файлы репозитория.

## Роли

### Владелец проекта
- принимает продуктовые, сюжетные и архитектурные решения;
- утверждает готовность задания к реализации;
- проверяет реализованные изменения;
- принимает или возвращает работу на доработку.

### ChatGPT — проектирование и контент
ChatGPT работает преимущественно с `docs/`:
- обсуждает с владельцем механику, сюжет, мир и интерфейс;
- ведёт спецификации игровых систем;
- ведёт базу мира: локации, объекты, NPC, действия, эффекты и квесты;
- создаёт и редактирует сцены, диалоги и описательный текст;
- поддерживает графы связей;
- формирует задания для Codex и переводит утверждённые задания в состояние `ready`;
- не изменяет игровой код в `game/`, если владелец проекта явно не поручил иное.

### Codex — реализация
Codex:
- перед работой читает корневой `AGENTS.md`;
- реализует только утверждённые задания из `docs/tasks/ready/`, если владелец явно не дал другую команду;
- читает связанные с заданием спецификации, сущности и существующий код;
- не придумывает самостоятельно новые сюжетные факты, баланс, правила мира или игровые механики;
- при неоднозначности, способной изменить дизайн, останавливается и запрашивает решение;
- после реализации создаёт отчёт о реализации и переводит результат в `review`;
- не считает задачу `done`, пока владелец проекта не принял результат.

## Структура

```text
/
├── README.md
├── AGENTS.md
├── game/                       # игровой код; рабочая зона Codex
├── assets/                     # игровые ассеты/ссылки и служебная информация
└── docs/
    ├── MASTER_SPEC.md          # карта канонической документации
    ├── systems/                # спецификации игровых систем
    ├── world/                  # база мира
    │   ├── hyperclusters/
    │   ├── locations/
    │   ├── objects/
    │   ├── npcs/
    │   ├── actions/
    │   ├── effects/
    │   └── quests/
    ├── content/
    │   ├── scenes/
    │   ├── dialogues/
    │   └── descriptions/
    ├── graphs/                 # Mermaid-графы и карты связей
    ├── templates/              # шаблоны проектных сущностей и задач
    └── tasks/
        ├── backlog/            # ещё проектируется; Codex не реализует
        ├── ready/              # утверждено и можно реализовывать
        ├── in_progress/        # находится в реализации
        ├── review/             # реализовано, ожидает проверки владельца
        └── done/               # принято владельцем
```

## Каноничность информации

Приоритет источников:
1. прямое актуальное решение владельца проекта;
2. канонические файлы `docs/`;
3. утверждённое задание в `docs/tasks/ready/` или более позднем статусе;
4. существующий код — источник фактической реализации, но не право самостоятельно менять дизайн;
5. история чатов и память AI — вспомогательный контекст, не источник истины.

Если утверждённое новое решение владельца противоречит документации, сначала должна быть обновлена каноническая документация, затем сформировано/обновлено задание на реализацию.

## Жизненный цикл задания

`backlog → ready → in_progress → review → done`

- `backlog`: идея или незавершённое проектирование.
- `ready`: решение утверждено владельцем и достаточно определено для реализации.
- `in_progress`: Codex начал реализацию.
- `review`: реализация завершена и ожидает проверки в игре.
- `done`: владелец принял результат.

Исходное задание после реализации не переписывается так, чтобы скрыть первоначальные требования. Отклонения и технические решения фиксируются в implementation report.

## Правило идентификаторов

Ключевые сущности получают стабильные ID. Ссылки между локациями, объектами, действиями, NPC, эффектами, квестами и сценами по возможности используют эти ID, чтобы граф мира и код могли однозначно ссылаться на одну сущность.

## Начало работы AI

Если AI впервые работает с репозиторием:
1. прочитать `README.md`;
2. прочитать `AGENTS.md`;
3. прочитать `docs/MASTER_SPEC.md`;
4. определить свою роль;
5. читать только документы, необходимые для текущей задачи;
6. не заменять отсутствующие данные догадками.
