# Nastya Story

Единый репозиторий проекта визуальной новеллы **Nastya Story**. Здесь находятся игровой код, каноническая проектная документация, база мира, контент и задания на реализацию.

## Главный принцип

**Чат сам по себе не является каноном.** Обсуждение становится каноническим после фиксации решения в соответствующем файле репозитория. При конфликте истории чата/памяти AI с актуальным репозиторием приоритет имеет репозиторий, если владелец проекта прямо не утвердил новое изменение.

## Куда идти за информацией

- [`AGENTS.md`](AGENTS.md) — обязательные правила работы ChatGPT/Codex.
- [`docs/MASTER_SPEC.md`](docs/MASTER_SPEC.md) — корневая карта (MOC) канонической базы знаний.
- [`docs/REPOSITORY_MAP.md`](docs/REPOSITORY_MAP.md) — карта влияния изменений и Change Impact Check; нужна прежде всего при правках.
- Тематические `README.md` внутри `docs/` — локальные карты разделов.

Контекст загружается слоями: **MASTER_SPEC → тематический MOC → нужная карточка → только необходимые прямые связи**. Не требуется рекурсивно читать весь `docs/`.

## Роли

### Владелец проекта

Принимает продуктовые, сюжетные и архитектурные решения, утверждает задания и принимает реализацию.

### ChatGPT — проектирование и контент

Работает преимущественно с `docs/`: проектирует механику и мир, ведёт канон, пишет/редактирует контент, поддерживает связи и графы, формирует задания Codex. `game/` без отдельного поручения не меняет.

### Codex — реализация

Реализует утверждённые требования в коде, использует TASK и прямые ссылки на нужные спецификации/сущности, не придумывает самостоятельно дизайн, сюжетные факты или баланс. Подробные правила — в [`AGENTS.md`](AGENTS.md).

## Владение каноном

- Каждый факт должен иметь один основной источник; вторичные документы ссылаются на него и не копируют подробности без необходимости.
- Центральный персонаж полностью описывается в своём `docs/world/characters/*_canon.md`.
- Если у персонажа есть отдельный canon-файл, его `npc_*.md` содержит только системную роль, расписание, местоположение и игровые связи.
- Общие механики живут в `docs/systems/`.
- Общие правила речи и экранных блоков Ren'Py живут в `docs/content/DIALOGUE_WRITING_GUIDE.md`; индивидуальный голос — только в карточке персонажа.
- Графы производны от канонических карточек и не являются конкурирующим источником истины.

## Приоритет источников

1. прямое актуальное решение владельца проекта;
2. актуальный основной канонический файл `docs/`;
3. утверждённый TASK в `ready` или более позднем статусе;
4. существующий код как источник фактической реализации, но не право самостоятельно менять дизайн;
5. история чатов и память AI как вспомогательный контекст.

Если новое решение владельца меняет канон, сначала синхронизируется документация и связанные представления, затем TASK/реализация.

## Задания Codex

Жизненный цикл:

`backlog → ready → in_progress → review → done`

- `backlog` — проектирование не закончено;
- `ready` — требования утверждены;
- `in_progress` — реализация идёт;
- `review` — реализация ждёт проверки;
- `done` — владелец принял результат.

Подробная карта: [`docs/tasks/README.md`](docs/tasks/README.md).

## Идентификаторы

Ключевые сущности получают стабильные машинные ID в `snake_case` (`loc_apartment_5_room`, `npc_nika`, `action_take_shower`, `effect_hungry` и т. п.). После появления ID не менять его только ради более красивого имени: стабильность ссылок важнее.

## Начало работы AI

Для новой задачи:

1. прочитать `AGENTS.md`;
2. открыть `docs/MASTER_SPEC.md`;
3. перейти в тематический MOC;
4. прочитать только нужные карточки и прямые зависимости;
5. если требуется правка — перед завершением выполнить Change Impact Check по `docs/REPOSITORY_MAP.md`;
6. отсутствующие данные не заменять догадками.
