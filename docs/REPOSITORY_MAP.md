# Repository Map — Nastya Story

> Практическая карта репозитория для ChatGPT, Codex и владельца проекта. Этот файл нужен, чтобы быстро понимать, где хранится конкретный тип информации и какие связанные файлы необходимо проверить при изменениях.

## Как пользоваться картой

Перед любой канонической правкой:

1. определить тип изменения;
2. найти основной канонический файл по таблице ниже;
3. проверить все связанные представления и зависимости;
4. внести изменения во все места, где этот факт или правило отражается;
5. после правки проверить отсутствие расхождений между карточками, графами, контентом, TASK и реализацией.

Изменение считается завершённым только после синхронизации всех затронутых представлений.

## Корень репозитория

| Файл / папка | Что содержит | Когда проверять |
|---|---|---|
| `README.md` | назначение репозитория, роли, общая структура, каноничность | при изменении структуры проекта или правил работы |
| `AGENTS.md` | обязательные правила работы ChatGPT/Codex | при изменении процесса проектирования/реализации |

| `assets/` | игровые ассеты и служебная информация об ассетах | при добавлении/изменении изображений, звука, UI-ассетов |
| `docs/` | каноническая проектная документация | почти при любом продуктовом изменении |

## Системы — `docs/systems/`

Хранят общие игровые правила, применимые к множеству сцен и локаций.

Ключевые файлы:

- `CHARACTERISTICS_SPEC.md` — характеристики, энергия, развитие;
- `RELATIONSHIPS_INVENTORY_WARDROBE_SPEC.md` — отношения, инвентарь, гардероб;
- `TIME_ACTIONS_QUESTS_EVENTS_SPEC.md` — время, действия, квесты, диспетчер событий;
- `UI_VISUAL_SYSTEM_SPEC.md` — UI/HUD;
- `NUTRITION_SPEC.md` — питание, голод, сытость;
- `ACTION_EFFECT_COOLDOWNS_SPEC.md` — кулдауны восстановительных эффектов;
- `TRANSPORT_SPEC.md` — транспорт и перемещение между суперхабами;
- `UNIVERSITY_SPEC.md` — университет, учебный прогресс, стипендия;
- `HUD_TEMPORARY_EFFECTS_SPEC.md` — временные значки HUD;
- `SITUATIONAL_EVENTS_SPEC.md` — ситуативные случайные/условные/сюжетные события.

### Если меняется механика

Проверить минимум:

- соответствующую системную спецификацию;
- связанные `docs/world/actions/`;
- связанные `docs/world/effects/`;
- связанные квесты;
- HUD/UI, если механика отображается игроку;
- сцены и диалоги, если они зависят от механики;
- TASK для Codex, если изменение должно быть реализовано.

## Персонажи

### `docs/world/characters/`

Содержит канон личности и внешности центральных персонажей.

- `nastya_canon.md` — полный канон Насти;
- `masha_canon.md` — полный канон Маши.

### `docs/world/npcs/`

Содержит системные карточки NPC: роль в мире, расписание, локации, участие в квестах и другие игровые связи.

Примеры:

- `npc_masha.md`;
- `npc_nika.md`;
- `npc_aslan.md`;
- `npc_olya.md`.

### Если меняется персонаж

Проверить:

- его `*_canon.md`, если это центральный персонаж;
- его `npc_*.md`, если есть системная NPC-карточка;
- `docs/content/SPEECH_BIBLE.md`, если меняется речь/характер общения;
- связанные сцены и диалоги;
- связанные квесты/расписания;
- графы, если меняются локации или связи персонажа.

## Локации — `docs/world/locations/`

Здесь находится физическая структура мира и карточки конкретных игровых мест.

Примеры:

- `apartment_building.md` — дом;
- `entrance_1_floor_3.md` — площадка третьего этажа;
- `apartment_5.md` — квартира Насти и Маши;
- `apartment_5_hallway.md`, `apartment_5_room.md`, `apartment_5_kitchen.md`, `apartment_5_bathroom.md`, `apartment_5_balcony.md` — помещения квартиры №5;
- `apartment_6_hallway.md` — входная карточка квартиры Ники и перечень её внутренних помещений;
- `loc_cafe.md` — кафе;
- `loc_masha_school.md` — школа Маши;
- `loc_bus_stop_residential.md` — автобусная остановка.

### Если меняется локация

Обязательно проверить:

1. основную карточку локации в `docs/world/locations/`;
2. карточку родительской локации, если меняется состав помещений/подлокаций;
3. `docs/graphs/residential_district.mmd` или другой world graph;
4. соответствующий navigation graph, если меняется доступность или маршрут игрока;
5. связанные объекты;
6. связанные NPC;
7. связанные сцены/описания;
8. квесты, если локация участвует в целях;
9. TASK/Codex-реализацию, если изменение должно появиться в игре.

Пример: добавление ванной в квартиру Ники требует одновременно обновить `apartment_6_hallway.md`, world graph и navigation graph; при дальнейшем создании отдельной карточки ванной нужно связать и её.

## Гиперкластеры — `docs/world/hyperclusters/`

- `hc_residential_district.md` — спальный район;
- `hc_university.md` — университет.

### Если меняется состав суперхаба

Проверить:

- карточку гиперкластера;
- дочерние location-карточки;
- world graph;
- navigation graph;
- транспортную спецификацию, если меняются точки входа/выхода.

## Графы — `docs/graphs/`

- `residential_district.mmd` — физическая/иерархическая структура стартового спального района;
- `residential_navigation.mmd` — реальные переходы игрока, включая быстрые переходы и будущие/закрытые маршруты.

Графы не являются отдельным источником истины, но должны синхронно отражать канонические карточки. Нельзя считать изменение локации завершённым, если карточка обновлена, а соответствующий граф остался старым.

## Контент — `docs/content/`

### Ключевые правила

- `SPEECH_BIBLE.md` — как говорят Настя и Маша;
- `DIALOGUE_WRITING_GUIDE.md` — как группировать речь, действия и повествование для игрового интерфейса.

### `docs/content/scenes/`

- `prologue.md` — канонический пролог, 28 августа;
- дневные и сюжетные сцены.

### `docs/content/dialogues/`

Готовые и модульные диалоги.

### `docs/content/descriptions/`

Описания локаций, объектов, действий и варианты авторского текста.

### Если меняется сюжетный факт

Проверить:

- соответствующую сцену;
- карточки персонажей;
- карточки локаций/NPC;
- квесты;
- графы, если факт меняет структуру или маршрут;
- `MASTER_SPEC`, если появился новый канонический документ.

## Квесты — `docs/world/quests/`

Пример:

- `quest_2026_08_29_first_normal_day.md` — первый управляемый день и чекпоинты.

### Если меняется квест

Проверить:

- quest-карточку;
- дневной outline/сцену;
- связанные действия;
- связанные локации/NPC;
- системную спецификацию квестов/событий;
- TASK на реализацию.

## Действия и эффекты

### `docs/world/actions/`

Семантика конкретных действий и их связи.

### `docs/world/effects/`

Карточки эффектов, например `effect_hungry.md`.

При изменении действия/эффекта сверять с системными таблицами времени, энергии и кулдаунов, а также с HUD при наличии визуального индикатора.

## Задания Codex — `docs/tasks/`

Жизненный цикл:

`backlog → ready → in_progress → review → done`

После изменения утверждённого дизайна проверить, не существует ли уже TASK, который описывает старую версию требования. Если существует — синхронизировать TASK до реализации либо явно создать корректирующее задание.

## Матрица влияния изменений

| Меняется | Основной файл | Обычно также проверить |
|---|---|---|
| внешность/характер персонажа | `world/characters/*_canon.md` | NPC, Speech Bible, сцены |
| расписание NPC | `world/npcs/*.md` | квесты, сцены, локации |
| помещение/локация | `world/locations/*.md` | родитель, world graph, navigation graph, сцены |
| маршрут игрока | location/hypercluster | navigation graph, transport, сцены |
| состав суперхаба | `world/hyperclusters/*.md` | locations, оба графа, transport |
| игровая механика | `systems/*.md` | actions, effects, UI, quests, TASK |
| эффект HUD | system/effect | HUD spec, effect card, actions |
| квест | quest card | scenes, actions, NPC, TASK |
| диалоговый стиль | `SPEECH_BIBLE.md` | character canon, dialogue scenes |
| формат сценариев | `DIALOGUE_WRITING_GUIDE.md` | новые/редактируемые сцены |
| сюжетный факт | scene/canon file | world cards, quests, graphs при необходимости |

## Обязательный Change Impact Check

Перед commit документационной правки AI должен мысленно ответить:

- Где хранится главный факт?
- Где этот же факт отображается вторично?
- Есть ли графическое/навигационное представление?
- Есть ли связанные NPC, действия, эффекты или квесты?
- Есть ли уже TASK для Codex со старой версией требования?
- Нужно ли обновить `MASTER_SPEC` или эту карту?

Если хотя бы один ответ неизвестен, сначала найти связанные файлы, а не завершать правку после изменения одного документа.
